Device, settings and every trial.

Why rate and not strength. The web vibration API has no amplitude control, and on this phone's motor duty-cycle steps tested at chance while tick rate tested reliably. So height is carried by how fast the ticks repeat, using only the four rates that were actually distinguishable.

Why it only changes at the boundaries. Calling vibrate() again cancels whatever is running, so re-firing every frame restarts the motor before it spins up and everything smears into flat static. Here a level is fired once and left alone until you cross into a different one.
